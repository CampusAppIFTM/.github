## 🎯 Sobre o Projeto

O **Campus App** é o projeto final da disciplina de Desenvolvimento de Dispositivos Móveis do IFTM — Campus Uberlândia. Durante **12 semanas**, as equipes da turma 3DS-A vivenciam o ciclo completo de desenvolvimento de software: da identificação de um problema real até a apresentação de um aplicativo funcional para uma banca avaliadora.

Cada aplicativo é construído em **React Native com Expo**, utilizando **Firebase** para autenticação e persistência de dados, e gerenciado com **metodologia ágil** (sprints quinzenais, daily meetings e backlog priorizado via MoSCoW).

## 💡 Motivação

> *A ideia começa no problema, não na tecnologia. Ninguém baixa um app que resolve um problema que não existe.*

Tecnologia se aprende de verdade resolvendo problemas reais. Em vez de exercícios isolados, cada equipe escolheu uma dor concreta da comunidade do campus — avisos que se perdem, controle de gastos, encontrar prestadores de serviço, dar voz a reclamações, aprender a programar, conectar monitores e estudantes — e está transformando essa dor em produto.

O projeto desenvolve, ao mesmo tempo:

- **Competência técnica** — todos os módulos do curso (navegação, estado global, persistência, APIs, recursos do dispositivo) aplicados em um produto integrado;
- **Trabalho em equipe** — papéis definidos, code review entre colegas e testes cruzados entre grupos;
- **Comunicação** — cada equipe encerra o trimestre apresentando seu app no **Shark Tank IFTM**, com pitch para banca de convidados.

## 🗓️ Plano de Aulas — 12 Semanas

| Semanas | Fase | Conteúdo | Entrega |
|:---:|---|---|---|
| **1–2** | 🧠 Ideação | Formação das equipes · Canvas do Problema · MVP Workshop (MoSCoW) | Backlog inicial |
| **3–4** | 🎨 Design & Navegação | Wireframes no Figma · Estrutura React Navigation | Telas navegáveis no Expo Go |
| **5–6** | 🔐 Sprint 1 — Identidade | Login com Google (`@react-native-google-signin`) · build nativo (`expo prebuild` + `run:android`) · rotas protegidas · sessão persistente | Autenticação funcionando |
| **7–8** | ⚙️ Sprint 2 — Lógica Core | Funcionalidade principal · FlatList · Firestore | MVP de ponta a ponta |
| **9–10** | ✨ Sprint 3 — Polimento | Estilização · Testes cruzados · Correção de bugs | App estável e estilizado |
| **11** | 🎤 Pitch Deck | Slides: Problema / Solução / Demo / Próximos Passos · Ensaio | Pitch de 5 minutos |
| **12** | 🦈 Shark Tank IFTM | Apresentação para banca · Demo ao vivo no Expo Go | Entrega final |

> ⭐ **Sprint 1 é idêntico para as 12 equipes** das duas turmas — todas implementam o mesmo login com Google (baseado no codelab de autenticação). Papéis de usuário começam no Sprint 2.

**Ritmo da sala:** toda aula começa com uma *Daily Meeting* de 10 minutos — cada equipe responde: *o que fizemos? o que faremos hoje? existe algum impedimento?*

**Avaliação:** Funcionamento (40%) · Pitch (30%) · Código (20%) · Colaboração (10%)

## 🛠️ Stack Comum

| Camada | Tecnologia |
|---|---|
| Framework | React Native + Expo |
| Build | Nativo — `expo prebuild` + `expo run:android` (não Expo Go) |
| Navegação | React Navigation (Stack · Bottom Tabs · Drawer) |
| Estado global | Context API |
| Autenticação | Login com Google via `@react-native-google-signin/google-signin` + Firebase |
| Banco de dados | Cloud Firestore (tempo real via `onSnapshot`) |
| Persistência local | AsyncStorage |
| Notificações | expo-notifications (agendamento local) |
| Distribuição | Expo Go + EAS Internal Distribution (QR code) |
